Step 1 • Workshop Overview

Build "GitHub Comic Heroes" with Google Antigravity 2.0

Welcome to the companion hands-on guide for the Getting Started with Google Antigravity 2.0 workshop. Instead of building disconnected hello-world scripts, we will use every feature of Antigravity 2.0 (Steps 2 through 9 of the official codelab) to build, test, automate, audit, and deploy a full-stack AI application: GitHub Comic Heroes.

AGENTIC VIGILANTE (#154)

How it works: Enter any GitHub username. The app fetches their real GitHub profile photo and top repositories, transforms their photo into a comic-book superhero using gemini-nano-banana-2.1 on Vertex AI, and generates 2–3 signature superpowers plus a comic speech bubble.

Stack: Node.js 22 • @google/genai • gemini-nano-banana-2.1 • Cloud Run

What You Will Practice (Steps 2 to 9)

  • Step 2 (Installation & Setup): Verifying Antigravity 2.0, Antigravity IDE, and Google Cloud credentials.
  • Step 3 (Antigravity 2.0 Interface): Multi-folder Projects, Project Settings, and parallel Conversation threads.
  • Step 4 (Slash Commands): Using /browser to launch Chrome and test the live Comic Card UI automatically.
  • Step 5 (Scheduling Commands): Using /schedule to refresh the Featured Hero card on a timer.
  • Step 6 (MCP Servers): Configuring and using the Google Cloud Run MCP server to deploy the app.
  • Step 7 (Artifacts): Using /plan to produce an Implementation Plan (with Mermaid diagrams) and a Walkthrough.
  • Step 8 (Antigravity IDE): Inspecting generated code diffs and chatting in the IDE Agent Panel.
  • Step 9 (Skills): Creating and triggering .agents/skills/code-review/SKILL.md via progressive disclosure.
Step 2 • Codelab Section 2

Installation & Environment Verification

After installing Antigravity 2.0 (the standalone agent command center) and Antigravity IDE, configure either Vertex AI (recommended with Application Default Credentials) or a Gemini API key in your environment so no secrets are ever hardcoded in your files:

Terminal Setup (Vertex AI ADC)
export GOOGLE_CLOUD_PROJECT="your-gcp-project-id" gcloud auth application-default login

Start your first prompt in Antigravity to verify your environment:

Prompt — Step 2
Check my local environment for this workshop: verify the installed Node.js and Python versions, confirm which Google Cloud project is currently configured in gcloud, and list the folders inside this workspace.

Step 5 • Codelab Section 5

Scheduling Commands: Autonomous Background Tasks

You can schedule recurring cron jobs or one-time timers either from the Schedule tab in the left sidebar or with the /schedule slash command. Antigravity wakes up reactively when the scheduled task completes.

Use this prompt to schedule a 60-second timer that refreshes the Featured Hero card in the background:

Prompt — Step 5 (/schedule)

Step 6 • Codelab Section 6

Model Context Protocol (MCP) Servers & Cloud Run Deploy

Go to Settings → Customizations → Installed MCP Servers and click Open MCP Config (~/.gemini/config/mcp_config.json) to view your configured MCP servers:

~/.gemini/config/mcp_config.json
{ "mcpServers": { "cloudrun": { "command": "npx", "args": ["-y", "@google-cloud/cloud-run-mcp"] } } }

Now ask Antigravity to deploy the application to Google Cloud Run using the MCP server:

Prompt — Step 6 (Cloud Run MCP)
Use the Cloud Run MCP server (`deploy_local_folder` or `list_services`) to deploy this project to Google Cloud Run in my Google Cloud project (region "us-central1", service name "github-comic-cards"), and return the live public Cloud Run URL.
Step 7 • Codelab Section 7

Artifacts: Implementation Plan, Diagrams & Walkthrough

Artifacts bridge the trust gap between autonomous agents and developers. When you run /plan, Antigravity generates a structured Implementation Plan artifact (with architecture diagrams and proposed changes) before writing code, followed by a Walkthrough artifact upon completion.

Option A: Build the Full App from Scratch with /plan

Prompt 7A — Full App /plan
/plan Design and build "GitHub Comic Heroes", a Node.js application (CLI in `src/cli.js` + Web UI in `src/server.js` and `public/index.html`) that takes any GitHub username, fetches their profile photo (`avatar_url`) and repositories from the GitHub API (`src/github.js`), and uses Vertex AI (`@google/genai` in `src/comic-ai.js`) to: 1. Transform their real GitHub profile photo into an American comic book superhero illustration using `gemini-nano-banana-2.1` (location `global`, aspect ratio `3:4`). 2. Generate their Comic Hero Alias, 2-3 Superpowers based on their top repositories/languages, and a speech bubble Battle Cry using `gemini-3.8-flash`. 3. Render the interactive Comic Book Trading Card and a "Hall of Heroes" gallery in a comic-styled web UI on port 8080. Include a Mermaid architecture diagram in the Implementation Plan.

Option B: Add a Live Feature (SVG README Badge) with /plan

Prompt 7B — Feature Extension /plan
/plan Add a `/api/card/:username/badge.svg` endpoint to `src/server.js` and a "Copy Markdown Badge" button on the comic card in `public/index.html` so developers can embed their Comic Hero title, archetype, and power rating directly in their GitHub profile README. Include a Mermaid flow diagram in the Implementation Plan.

Step 9 • Codelab Section 9

Skills: Progressive Disclosure with .agents/skills/

Skills package domain instructions and helper scripts in .agents/skills/<skill-name>/SKILL.md. Antigravity reads only the YAML frontmatter (name and description) at startup and loads the full instructions and scripts only when your prompt matches the skill.

This repository includes .agents/skills/code-review/SKILL.md (along with its AST verifier script .agents/skills/code-review/scripts/ast_audit.py) and demo_bad_code.py from the official Codelab.

1. Trigger the Code Review Skill

Prompt 9A — Audit @demo_bad_code.py
review the @demo_bad_code.py file

2. Apply the Fixes & Verify

Prompt 9B — Fix & Verify
Fix the bugs and performance issues identified in @demo_bad_code.py (handle the None return when user ID 3 is missing, remove the blocking `time.sleep(0.1)` inside the loop, and avoid shadowing the built-in `id`), then run the script to verify it completes cleanly without errors.
